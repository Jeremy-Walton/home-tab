# dropdown-menu

2026-07-03 — golden pair via CLI registry, three-way merge (style `radix-luma` → `base-luma` variant fetched by URL; progressive mode, no `--overwrite`). Verdict: wrapper was CUSTOMIZED (missing `cn-menu-target cn-menu-translucent` classes present in both goldens — a deliberate omission, preserved). `git merge-file` produced 4 conflicts because Base UI's `Menu` reorders `Sub`/`SubTrigger`/`SubContent` earlier in the file relative to the radix layout; hand-resolved against `menus.md`, then rebuilt the file directly from the base golden's structure to be certain no stale radix code survived the reordering (the skill's own warning: "a clean merge is NOT proof of a clean file" — one non-conflicted hunk in the raw merge output still contained a stray `IconPlaceholder` inside `SubTrigger`, caught by the sweep, not by the merge).

## Changed

- `src/components/ui/dropdown-menu.tsx` — replaced with the base-luma structure (`Menu` from `@base-ui/react/menu`), with the `cn-menu-target cn-menu-translucent` classes omitted from `DropdownMenuContent`/`DropdownMenuSubContent` (`dropdown-menu.tsx:39`, `dropdown-menu.tsx:145`) to preserve the pre-existing customization, and `IconPlaceholder` resolved to this project's phosphor `CheckIcon`/`CaretRightIcon` imports (icon-resolution artifact, same as other components). Part mapping: `Content` → `Portal > Positioner > Popup` (align/alignOffset/side/sideOffset move to `Positioner`; CSS vars renamed `--radix-dropdown-menu-content-available-height` → `--available-height`, `--radix-dropdown-menu-trigger-width` → `--anchor-width`, `--radix-dropdown-menu-content-transform-origin` → `--transform-origin`), `Label` → `GroupLabel`, `Sub` → `SubmenuRoot`, `SubTrigger` → `SubmenuTrigger`, `SubContent` → rebuilt as a call to `DropdownMenuContent` itself (not a separate primitive part — matches the base registry's own composition, `dropdown-menu.tsx:129-152`), `ItemIndicator` → split into `CheckboxItemIndicator`/`RadioItemIndicator` per item type. `DropdownMenuItem`/`CheckboxItem`/`RadioItem` lose the `onSelect` prop entirely (Base UI `Item.Props` has no such prop — see consumer changes below).
- `src/components/EntityOptionsMenu.tsx` and `src/components/ImportExportBar.tsx` — both consumers, repointed during the strangler step, byte-identical after the finalize rename. Two call-site changes in each, per `consumer-props.md`/`menus.md`:
  - **`onSelect={fn}` → `onClick={fn}`** on every `DropdownMenuItem` (`EntityOptionsMenu.tsx:61,67,74`; `ImportExportBar.tsx:54-55`). Base UI's `Menu.Item` has no `onSelect`; the equivalent is `onClick` + `closeOnClick` (`closeOnClick` defaults `true` on plain `Item`, matching Radix's "closes on select" default — no explicit `closeOnClick` needed here since none of these items open a checkbox/radio item, the one case where the Base default flips to `false`).
  - **Nested `asChild` composition rewritten as nested `render`**: both files stack `TooltipTrigger asChild > DropdownMenuTrigger asChild > Button` on one element. `TooltipTrigger` itself is untouched (`tooltip.tsx` is still on Radix, migrated separately) and keeps `asChild` — Radix's `Slot` clones whatever single child it's given and forwards unrecognized props/ref straight through, so it doesn't matter that the child is now a Base UI component. Only the inner `DropdownMenuTrigger asChild><Button>...</Button></DropdownMenuTrigger>` became `DropdownMenuTrigger render={<Button>...</Button>} />` (`EntityOptionsMenu.tsx:43-56`, `ImportExportBar.tsx:40-51`), matching the `render`-prop composition pattern documented in `disclosure.md` for `Toolbar.Button render={<Toggle/>}`. Verified against `node_modules/@base-ui/react/menu/trigger/MenuTrigger.js`: unrecognized props (including an externally supplied `ref`, which React 19 now allows as a plain prop on function components) flow through `elementProps` into the final merged render target, so Radix's `Slot`-forwarded hover/focus handlers from `TooltipTrigger` still reach the underlying `Button` correctly.

Leftover scan clean: `grep -n "radix-ui\|@radix-ui\|IconPlaceholder"` on `src/components/ui/dropdown-menu.tsx`, `src/components/EntityOptionsMenu.tsx`, and `src/components/ImportExportBar.tsx` → no matches. Typecheck, ESLint, Vitest (10/10), and production build all pass, matching the pre-migration baseline.

## Left alone

- `src/components/ui/tooltip.tsx` — still on Radix; migrated separately. Both consumers here keep `TooltipTrigger asChild` unchanged.

## Behavior changes

None expected. `closeOnClick` defaults to `true` on plain `Menu.Item` (this app uses only plain items, no checkbox/radio items), matching Radix's prior "closes on select unless prevented" behavior — no consumer here ever called `event.preventDefault()` in `onSelect` to keep the menu open, so there's nothing to flip. The nested-trigger composition (`TooltipTrigger asChild` wrapping a `render`-based `DropdownMenuTrigger`) is a novel pattern for this codebase; flagging it for hand-verification below out of caution even though the code-level analysis supports it working identically to before.

## Verify by hand

- Hover a link tile or dashboard tab's "…" button: tooltip ("Link options"/"Dashboard options"/"Import / export") should appear after the usual hover delay, same as before.
- Click the "…" button: dropdown menu opens (Edit/Move to…/Delete, or Export/Import) — this is the main risk area since the trigger composition changed structurally. If the menu fails to open, or the tooltip stays stuck open after opening the menu, that's this migration's fault.
- Click **Edit**: menu closes, edit modal opens. Click **Delete**: menu closes, confirm dialog opens; deleting is disabled for the last remaining dashboard.
- Hover **Move to…**: submenu opens listing other dashboards; click one: link moves, both menus close.
- **Import/Export bar**: click **Export**, confirm a JSON file downloads. Click **Import**, confirm the hidden file input opens a file picker and imported data replaces app state.
- Keyboard: open a menu with Enter/Space on the trigger, arrow through items, Enter to activate, Esc to close and return focus to the trigger button.
